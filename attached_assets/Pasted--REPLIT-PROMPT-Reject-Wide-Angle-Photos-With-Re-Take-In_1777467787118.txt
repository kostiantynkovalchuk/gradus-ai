# REPLIT PROMPT: Reject Wide-Angle Photos With Re-Take Instructions

## Problem

3 out of 50 vodka corrections are catastrophic failures (AI=0%, expert=60-100%) caused by wide-angle/distant photos where labels are unreadable. These photos waste API costs ($0.12 each) and produce useless reports that hurt overall accuracy metrics.

Reports #59, #111 — AI says "distance and resolution make identification impossible" but still generates a report with zeros. Report #86 — AI says "no vodka section visible" with high confidence.

## Solution

After initial analysis, if ALL categories have low confidence OR the notes mention distance/resolution issues, reject the photo and ask the agent to re-take closer photos.

## Implementation

In the function that processes the analysis result and sends the Telegram report (likely in `bot.py` or the orchestration function), add a check BEFORE sending the scored report:

```python
def _should_reject_photo(vision_result: dict) -> bool:
    """Check if photo quality is too low for reliable analysis.
    
    Returns True if the photo should be rejected with re-take instructions.
    """
    # Check 1: All categories have low confidence
    categories = ["vodka", "cognac", "wine", "sparkling"]
    confidences = []
    for cat in categories:
        cat_data = vision_result.get(cat, {})
        conf = cat_data.get("confidence", "low")
        confidences.append(conf)
    
    all_low = all(c == "low" for c in confidences)
    
    # Check 2: All facings are null or zero across all categories
    all_null_or_zero = True
    for cat in categories:
        cat_data = vision_result.get(cat, {})
        for key, val in cat_data.items():
            if "facings" in key and val is not None and val > 0:
                all_null_or_zero = False
                break
    
    # Check 3: Notes mention distance/resolution problems
    notes = (vision_result.get("notes", "") or "").lower()
    distance_keywords = [
        "distance", "resolution", "too far", "too small",
        "cannot read", "unreadable", "impossible to identify",
        "low resolution", "wide-angle", "wide angle",
        "відстань", "роздільн", "далеко", "нечитабельн",
        "неможливо", "занадто дрібн", "занадто далек"
    ]
    has_distance_issue = any(kw in notes for kw in distance_keywords)
    
    # Check 4: Shelf scan has only vague entries (no specific brand counts)
    shelf_scan = vision_result.get("shelf_scan", [])
    vague_scan = False
    if shelf_scan:
        # If all rows use "x20+", "x30+", "mixed", "various" — it's too vague
        vague_count = 0
        for row in shelf_scan:
            brands = row.get("brands", [])
            for brand in brands:
                if any(w in brand.lower() for w in ["x20+", "x30+", "mixed", "various", "невизначен", "unknown"]):
                    vague_count += 1
        if vague_count >= len(shelf_scan):
            vague_scan = True
    
    # Reject if: (all low confidence) OR (all null/zero AND distance issue)
    if all_low:
        return True
    if all_null_or_zero and has_distance_issue:
        return True
    if all_null_or_zero and vague_scan:
        return True
    
    return False
```

## Where to add the check

In the report generation flow, AFTER Claude Vision returns the analysis but BEFORE scoring and sending the report:

```python
# Pseudo-code — adapt to actual function names in bot.py

async def process_photos(update, context, photos_b64):
    # Step 1: Run Claude Vision analysis
    vision_result = await analyze_photos(photos_b64)
```

## Important: Save rejected reports for analytics

When rejecting a photo, still save a minimal record to the database so we can track:
- How many photos are rejected (rejection rate)
- Whether the agent re-submitted closer photos
- Which agents consistently send wide-angle photos (training opportunity)

```python
# In db.py — add a rejection record
async def save_rejected_report(agent_id, trade_point_name, reason="wide_angle"):
    """Save a minimal record for rejected photos."""
    conn = get_connection()
    try:
        with conn.cursor() as cur:
            cur.execute("""
                INSERT INTO photo_reports 
                    (agent_id, trade_point_name, score, passed, errors, scoring_version, photo_count)
                VALUES (%s, %s, 0, false, %s, 'v2_rejected', 1)
                RETURNING id
            """, (
                agent_id, 
                trade_point_name,
                json.dumps([{"code": "REJECTED", "description": f"Photo rejected: {reason}"}])
            ))
            report_id = cur.fetchone()[0]
            conn.commit()
            logger.info(f"Saved rejected report #{report_id} for agent {agent_id}")
            return report_id
    finally:
        conn.close()
```
