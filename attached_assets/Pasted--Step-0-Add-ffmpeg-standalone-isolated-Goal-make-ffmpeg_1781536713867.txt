# Step 0 — Add ffmpeg (standalone, isolated)

**Goal:** make `ffmpeg` available on the Render service so Sara's voice pipeline can transcode TTS mp3 → Telegram OGG/Opus.
**Why standalone:** this is a Dockerfile change → full image rebuild → restart of the whole service (all five live bots). Doing it as its own commit with nothing else in flight means a clean rollback if the build misbehaves, and certainty about what caused any change.
**When:** quiet window (now — past Ukraine business hours; clear of the Maya HR morning rush and scheduled GradusMedia posts).

> This is an **implementation** prompt — separate from the audit (Rules.rtf). It does exactly one thing. Do not bundle any Sara code with it.

---

## The change

Open the root `Dockerfile`. Find the existing apt install line (audit-confirmed it looks like this):

```dockerfile
RUN apt-get update && apt-get install -y \
    curl gcc libpq-dev pkg-config poppler-utils \
    antiword tesseract-ocr tesseract-ocr-ukr tesseract-ocr-rus
```

Add `ffmpeg` to the list — **minimal diff, nothing else changed, no reordering, no cleanup lines added:**

```dockerfile
RUN apt-get update && apt-get install -y \
    curl gcc libpq-dev pkg-config poppler-utils \
    antiword tesseract-ocr tesseract-ocr-ukr tesseract-ocr-rus \
    ffmpeg
```

> Match the actual file. If the real line differs from the audit quote (extra packages, line continuations), just append ` ffmpeg` to the install list — do not rewrite the surrounding Dockerfile.

---

## Commit (its own, isolated)

```bash
git add Dockerfile
git commit -m "build: add ffmpeg to image (Sara voice pipeline prerequisite)"
git push origin main
```

Render auto-deploys from `main`. Nothing else should be in this commit.

## Verify (in order — do not start Sara work until all pass)

1. **Build succeeds.** Watch the Render deploy logs to completion. If the build *fails*, Render keeps the previous image live — you are not down, you just roll back the commit and investigate. A failed build is the main (and self-protecting) risk.
2. **ffmpeg present.** In the Render shell:
   ```bash

   ```
   Expect a version banner, not "command not found".
3. **Service is up.** Hit the health/status route (the `status_router` root) and confirm 200.
4. **All five bots still respond** (Rules.rtf §5 post-deploy reconciliation — the restart re-registered every webhook on startup):

## Rollback (if anything looks wrong)

```bash
git revert HEAD && git push origin main
```

Reverting the single commit returns the image to its pre-ffmpeg state on the next auto-deploy. Because nothing else was in the commit, the revert is clean and total.
