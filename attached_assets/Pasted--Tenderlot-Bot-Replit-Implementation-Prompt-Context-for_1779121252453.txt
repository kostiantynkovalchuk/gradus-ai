# Tenderlot Bot — Replit Implementation Prompt

> **Context for the agent:** You are building the skeleton of a production Telegram bot for AVTD (Ukraine's largest alcohol distributor). The bot will notify tenderlot.net users about tender events via Telegram, replacing/augmenting their current email notification system. This Replit project is the development environment; the production target is Render.com with a real MariaDB integration. For now, use mocks — do NOT attempt to connect to any real database.

## 1. Goals of This Build

Deliver a **runnable Telegram bot skeleton** that:

1. Accepts `/start`, walks the user through consent → `request_contact` → phone matching against a mock `users` table → confirmation message.
2. Runs a **polling loop** every 30 seconds that reads a mock `tender` table, finds tenders where `start_mail_status = 1` AND not yet sent to Telegram, and dispatches a notification to all matched users with the `Відкрити тендер` inline button.
3. Tracks delivery state in a local SQLite database so duplicate sends are prevented.
4. Supports `/help`, `/unlink`, and `/status` commands.
5. Handles edge cases: user blocks bot, phone not found, duplicate `/start`.

**Out of scope for this build (do NOT implement):**

- T−10 minute reminders
- "Your bid was outbid" notifications
- Tender completion / winner notifications
- Two tender types differentiation (auction vs proposal collection) — single template is fine
- Currency handling beyond a placeholder field
- Email fallback
- Web dashboard
- Real database connection

- **Tests:** `pytest` with at least one test per service layer
- **Linting:** `ruff` + `mypy` for static checks

## 4. Database Schemas

### 4.1 Mock tenderlot tables — mirror the REAL schema we'll connect to later

Source of truth: production MariaDB at AVTD has these tables — we mirror them so the swap to production requires only changing the connection string and removing the mocks layer.

**`tenderlot_user` (mock of `users` view)**
```python
class TenderlotUser(Base):
    __tablename__ = "tenderlot_user"
    id: Mapped[int] = mapped_column(primary_key=True)
    phone: Mapped[str] = mapped_column(String(20), index=True)  # E.164 format
    full_name: Mapped[str] = mapped_column(String(255))
    email: Mapped[str | None] = mapped_column(String(255), nullable=True)
    role: Mapped[str] = mapped_column(String(20))  # "supplier" | "carrier"
    is_active: Mapped[bool] = mapped_column(default=True)
```

**`tenderlot_tender`**
```python
class TenderlotTender(Base):
    __tablename__ = "tenderlot_tender"
    id: Mapped[int] = mapped_column(primary_key=True)
    number: Mapped[str] = mapped_column(String(50))
    title: Mapped[str] = mapped_column(String(500))
    tender_type: Mapped[str] = mapped_column(String(50))  # "auction" | "proposal_collection"
    start_price: Mapped[float | None] = mapped_column(Float, nullable=True)
    currency: Mapped[str] = mapped_column(String(3), default="UAH")  # ISO code
    starts_at: Mapped[datetime]
    ends_at: Mapped[datetime]
    start_mail_status: Mapped[int] = mapped_column(default=0)  # 0=not sent, 1=sent
    end_mail_status: Mapped[int] = mapped_column(default=0)
    target_role: Mapped[str] = mapped_column(String(20))  # "supplier" | "carrier" | "both"
```

### 4.2 Bot's own tables — Neon PostgreSQL in production, SQLite in dev

**`bot_user`** — linking Telegram identity to tenderlot user
```python
class BotUser(Base):
    __tablename__ = "bot_user"
    id: Mapped[int] = mapped_column(primary_key=True)
    telegram_id: Mapped[int] = mapped_column(BigInteger, unique=True, index=True)
    telegram_username: Mapped[str | None] = mapped_column(String(100), nullable=True)
    phone: Mapped[str] = mapped_column(String(20), index=True)
    tenderlot_user_id: Mapped[int] = mapped_column(index=True)
    consent_given_at: Mapped[datetime]
    linked_at: Mapped[datetime]
    is_active: Mapped[bool] = mapped_column(default=True)
    unlinked_at: Mapped[datetime | None] = mapped_column(nullable=True)
```

**`notification_log`** — what we've sent, idempotency key
```python
class NotificationLog(Base):
    __tablename__ = "notification_log"
    id: Mapped[int] = mapped_column(primary_key=True)
    bot_user_id: Mapped[int] = mapped_column(index=True)
    tender_id: Mapped[int] = mapped_column(index=True)
    notification_type: Mapped[str] = mapped_column(String(50))  # "tender_start" for now
    sent_at: Mapped[datetime]
    telegram_message_id: Mapped[int | None] = mapped_column(nullable=True)
    delivery_status: Mapped[str] = mapped_column(String(20))  # "sent" | "failed" | "blocked"
    error_message: Mapped[str | None] = mapped_column(Text, nullable=True)

    __table_args__ = (
        UniqueConstraint("bot_user_id", "tender_id", "notification_type",
                         name="uq_no_duplicate_notifications"),
    )
```

The unique constraint is critical — it guarantees we never send the same notification twice even if the polling worker double-runs.

## 6. The User Flow — Detailed

### `/start` handler (`src/tenderlot_bot/bot/handlers/start.py`)

1. Check if `telegram_id` is already in `bot_user` table.
   - If yes AND `is_active=True` → show "Ви вже підключені" with brief profile info
   - If yes AND `is_active=False` → offer to re-link
   - If no → show consent screen
2. **Consent screen:** message text + two inline buttons: `✅ Згоден` and `❌ Не згоден`
3. On `❌` → polite goodbye, no further action
4. On `✅` → store `consent_given_at` timestamp, show `request_contact` keyboard with single button `📱 Поділитись контактом`

### Contact handler (`src/tenderlot_bot/bot/handlers/contact.py`)

1. Receive `Contact` from PTB update
2. Normalize phone to E.164 (`+380...` format)
3. Query `tenderlot_user` table by phone
4. **If no match:**
   ```
   На жаль, ваш номер не знайдено в системі tenderlot.net.
   Перевірте, що в профілі вказано актуальний номер, і спробуйте знову.
   ```
5. **If match:** create `bot_user` row, send confirmation:
   ```
   ✅ Прив'язку успішно завершено.

   Профіль:
   Ім'я: [full_name]
   Роль: [роль українською]

   Тепер ви отримуватимете сповіщення про тендери в Telegram.

   Команди:
   /help — допомога
   /status — ваш профіль і статистика
   /unlink — відписатися від сповіщень
   ```

### `/unlink` — mark `bot_user.is_active=False`, set `unlinked_at`, send confirmation. Do NOT delete the row (we need it for audit).

### `/help` — show command list and short FAQ.

### `/status` — show profile info + count of notifications received this week.

## 8. Polling Worker — The Heart of the Bot

`src/tenderlot_bot/services/polling_worker.py`:

```python
class PollingWorker:
    """
    Reads tenderlot.tender every N seconds.
    For each row where start_mail_status=1 AND no notification_log row exists
    for (bot_user, tender, 'tender_start') — dispatches via notifier.

    Idempotent by design: the unique constraint on notification_log
    prevents duplicates even across restarts.
    """

    async def run_forever(self) -> None:
        while True:
            try:
                await self._poll_once()
            except Exception:
                logger.exception("Polling cycle failed; will retry next interval")
            await asyncio.sleep(settings.poll_interval_seconds)

    async def _poll_once(self) -> None:
        # 1. Fetch up to poll_batch_size tenders with start_mail_status=1
        # 2. For each: find target users (matching role), filter out those
        #    already notified for this tender, dispatch via notifier
        # 3. Log each send (success/failure) to notification_log
```

Critical details:

- **Start the worker on FastAPI startup** via `asyncio.create_task`
- **Graceful shutdown** on SIGTERM (Render and Replit both send it)
- **Backoff on Telegram API rate limits** — PTB handles this internally, just don't fight it
- **One try/except per tender, not per cycle** — one failed send must NOT block others

## 14. Code Quality Requirements

- **Type hints everywhere.** `mypy --strict` should pass on `src/`.
- **No bare `except Exception` blocks** without logging and re-raising or explicit recovery.
- **Logging at INFO for state changes, DEBUG for detailed flow, ERROR for failures with stack trace.**
- **All datetimes timezone-aware** — use `datetime.now(timezone.utc)`, never naive.
- **No print statements** — use logger.
- **No magic strings for notification types** — use an Enum:
  ```python
  class NotificationType(str, Enum):
      TENDER_START = "tender_start"
  ```
