Two admin panel fixes in Maya HR bot. Both are pre-existing bugs 
(unrelated to today's broadcast/menu commits).

=== FIX 1: admin_cmd:logs returns 400 Bad Request silently ===

Production log evidence:
  🔘 Callback query: admin_cmd:logs
  HTTP Request: POST .../sendMessage "HTTP/1.1 400 Bad Request"
  ✓ Admin button callback processed   ← lies about success

User-facing impact: HR clicks 🔍 Logs, gets nothing visible.

WORKFLOW CONTEXT (important for designing the fix):
HR uses this to identify people whose authentication failed and 
proactively contact them. They want to copy-paste names+phones from 
the Telegram output and message those users directly. So the data 
that matters is FAILED attempts with enough detail to act on.

Investigate:
1. Find the handler for cmd == 'logs' in 
   backend/routes/telegram_webhook.py (after line 1286).
2. Identify the root cause of the 400 — most likely:
   (a) Message > 4096 chars (Telegram limit), or
   (b) Markdown parse_mode with unescaped special chars in phone 
       numbers / names.
3. Look at what the handler currently selects — probably all 
   verification attempts. Note how many rows are in the underlying 
   table.

Fix:
- Default behavior: show only FAILED verification attempts, last 
  50 entries, newest first. Successful attempts are not actionable 
  for HR and just add noise.
- Format each entry on its own line: 
  "❌ {timestamp} | {name or 'unknown'} | {phone} | {reason}"
  where reason is whatever the failure category is ('not_in_sed', 
  'not_whitelisted', 'phone_mismatch', etc).
- If the result is still too long, chunk into messages of max 
  ~3500 chars each, same pattern as the listusers fix below.
- Send with parse_mode=None (plain text) — phone numbers and names 
  often contain characters that break Markdown.
- Empty-state message if no failures: "✅ Невдалих спроб не 
  зафіксовано. Всі верифікації успішні."
- Header on first chunk: "🔍 Невдалі верифікації (останні N):"
- Replace the dishonest try/except that logs success regardless. 
  If the sendMessage status is not 200, log the response body AND 
  send the user a short fallback message ("⚠️ Помилка завантаження 
  журналу").
