Two bugs found during the first end-to-end smoke test of the bot.
Bug 1 — Duplicate consent acknowledgment.
After the user taps "✅ Згоден", the bot sends this message twice in a row:

Чудово! Тепер натисніть кнопку нижче, щоб поділитися своїм номером телефону. Ми перевіримо, чи є ваш номер у системі tenderlot.net.

Likely cause: the consent callback handler is registered twice, OR the consent acknowledgment is sent both from the CallbackQuery handler AND from a follow-up state transition. Find the duplicate path and remove it.
Add a test in tests/test_handlers.py (create if missing) that verifies the consent flow sends exactly ONE acknowledgment message, not two. Mock the PTB context and assert context.bot.send_message.call_count == 1 (or whatever the actual send mechanism is).
Bug 2 — Phone matching fails on real Telegram contacts.
When a real user shares their contact via Telegram's native "Share Contact" feature, the matcher fails to find them even though they're in the mock DB.
Test case: user with phone +34692480784 exists in tenderlot_user table. User shares their Telegram contact (which has phone_number 34692480784 — note: Telegram strips the + prefix in Contact.phone_number). Bot responds with "Не вдалося розпізнати номер телефону".
Root cause is likely in src/tenderlot_bot/services/matcher.py — the E.164 normalization should handle phone numbers with OR without the leading +, with OR without leading 00, with OR without spaces and dashes. Verify the normalization logic against these inputs:
"+34692480784"   → "+34692480784"
"34692480784"    → "+34692480784"
"0034692480784"  → "+34692480784"
"+34 692 480 784" → "+34692480784"
"+34-692-480-784" → "+34692480784"
ALL of these inputs must normalize to the same E.164 form before DB lookup.
Also: log the normalized phone at INFO level in the contact handler so we can debug similar issues in the future without code changes:
pythonlogger.info("Contact received: raw=%r normalized=%r", contact.phone_number, normalized)
logger.info("Lookup result: user_id=%s", user.id if user else None)
Add tests in tests/test_matcher.py covering each of the input variants above.
