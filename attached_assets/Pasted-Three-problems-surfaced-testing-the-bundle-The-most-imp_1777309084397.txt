Three problems surfaced testing the Сільпо bundle. The most important: classification is failing on PDF and Excel documents.
Bug 1 (urgent): Document classifier defaults everything to "other".
Сільпо's bundle has 12 documents — main contract PDF, 4 appendix PDFs, 6 Excel files (specifications, price lists, schedules, etc.), plus 2 Word files. Every PDF and Excel got classified as other. Only the two Word files (containing 'ПР' and 'Ризики' in their filenames) got correct types.
Likely causes:

PDF text extraction may be failing or returning insufficient content for the Haiku classifier prompt to work with. Check what the classifier actually sees as input for these PDFs.
Excel classifier input is fundamentally weak — openpyxl extracts cell values with no contextual structure, so distinguishing specification.xls from price-list.xls requires content-level understanding.
Filename heuristics don't match Сільпо's naming convention. Their files use "т.ф. 188" (типова форма 188 — the legal form number for retail supply contracts) which was not in the heuristic list.

Three fixes needed in priority order:

Add filename heuristics for Сільпо's naming patterns:

filename contains 'договір' (any form) → main_contract
filename contains 'т.ф.' followed by digits → main_contract (typical form pattern)
filename contains 'додаток' or 'додатки' AND ends with .pdf → additional_agreement
filename contains 'специф' AND .xls → specification
filename contains 'прайс' or 'price' AND .xls → price_list
filename contains 'графік' or 'график' AND .xls → schedule
filename contains 'накладна' AND .xls → other (correctly — this is a sample document, not analyzable)
filename contains 'пакувальний' or 'packing' → other


Log what the classifier actually receives for each document — filename + first 500 chars of extracted text. Save to a debug log for these problem PDFs/XLS files. Helps diagnose whether PDF extraction is broken or whether the LLM prompt is just weak.
Add a graceful fallback message in the engagement workspace when zero documents are analyzable: "Жоден документ не класифіковано як договір. Натисніть на тип документа для зміни." instead of just hiding the analyze button silently.

Bug 2 (medium): No way for lawyers to fix misclassification.
Add a UI to manually override document_type. Click on the type label on a document card → dropdown appears with all valid document_type values → select one → PATCH /api/contracts/documents/{doc_id}/type → row updates. This unblocks testing today and gives lawyers an escape hatch for any future classifier mistakes.
Bug 3 (small): "Не потребує аналізу" wording is correct but confusing on other.
When document_type='other', the label should read "Тип не визначено" instead of "Не потребує аналізу" — the latter implies "we deliberately don't analyze this kind of doc" but other actually means "we don't know what kind of doc this is." Different message, different meaning.
After Bug 2 lands, manually set document_type='main_contract' on the Сільпо PDF, document_type='additional_agreement' on the appendix PDFs, document_type='specification' on the spec xls files, and re-trigger analysis. That'll let us actually test the analyzer on Сільпо while Bug 1's heuristics get refined.
