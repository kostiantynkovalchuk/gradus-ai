THE SORT — clause numbers do NOT sort as strings ("7.10" < "7.2" alphabetically is
WRONG). Implement a NATURAL/NUMERIC clause sort:
- Parse clause_ref into numeric components: "7.10" → (7,10), "7.2" → (7,2), so
  7.2 < 7.9 < 7.10 < 7.17. Multi-level: "5.1.7" → (5,1,7).
- RANGE refs (e.g. "7.3–7.17"): sort by the START endpoint → (7,3). Handle the dash

- SECTION-level refs ("7", "п.7"): strip the "п." prefix, sort as (7,) — comes before
  7.1.
- APPENDIX refs ("Додаток 8 п.1.4.2", or bare "п.2.1" referring to an appendix):
  these sort AFTER all body clauses (matching how the contract is laid out — body
  first, then appendices). Detect appendix refs and give them a sort key that places
  them after body refs, then order among themselves naturally.
- Anything unparseable: sort to the END (don't crash — Rule 3; a weird ref shouldn't
  break the whole list). Wrap the parse in try/except, fall back to a high sort value.
