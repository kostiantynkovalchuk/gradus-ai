## Step 2 — The migration

Append ONE entry to `MIGRATIONS` in `backend/db_migrations.py`.
Idempotent, per CLAUDE.md section 3 — use the pg_constraint guard pattern:

```sql
DO $$
BEGIN
  IF NOT EXISTS (
    SELECT 1 FROM pg_constraint WHERE conname = 'chk_hunt_candidates_hr_decision'
  ) THEN
    ALTER TABLE hunt_candidates
      ADD CONSTRAINT chk_hunt_candidates_hr_decision
      CHECK (hr_decision IN ('pending','approved','rejected','saved','hired'));
  END IF;
END $$;
```

Same pattern for `chk_hr_broadcast_log_status` and
`chk_hunt_sources_channel_type`, using the Step-1-confirmed sets.
Naming follows the going-forward `chk_<table>_<column>` convention
(Sara's pattern). NULL handling: CHECK passes NULLs by design — do not
add NOT NULL in this migration; that is a separate decision.

Tables are small (<200 rows each) and data is verified clean, so plain
ADD CONSTRAINT (which validates existing rows) is safe — no NOT VALID
staging needed.
