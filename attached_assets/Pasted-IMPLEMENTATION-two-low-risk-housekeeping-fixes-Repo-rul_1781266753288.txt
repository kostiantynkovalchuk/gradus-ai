FIX 1 — Animated sand clock in the analysis ticker (CSS only, frontend)
═══════════════════════════════════════════════════════════════
The in-progress ticker currently shows a static ⏳ inside the button text
(solomon_template.html ~line 1046):
  `⏳ Аналізую договір… це займає близько 5 хвилин (${elapsed}с)`

We want the sand clock gently animated (rotate/flip) as a nice "it's working" cue.

CRITICAL constraints:
- PURE CSS @keyframes animation (GPU/compositor) — NOT JavaScript-driven. Zero
  perf cost, no impact on the poll loop or backend.
- The animated icon must be a SEPARATE element, NOT part of the ${...} text string
  that the poll rewrites every 8 seconds. If the ⏳ stays inside the rewritten
  textContent, the animation RESTARTS on every tick (stutters every 8s). So:
  * Restructure the button content into: an animated icon element + a text element.
    e.g. button.innerHTML = `<span class="solcon-hourglass">⏳</span> <span
    class="solcon-ticker-text">Аналізую договір… це займає близько 5 хвилин
    (${elapsed}с)</span>`, OR put the icon as a CSS ::before / sibling span that the
    8s update does NOT touch — only the text span's content is rewritten each tick.
  * The key requirement: the icon element persists across ticks so its CSS animation
    runs continuously; only the seconds text updates.
- Add a CSS rule (in the existing <style> block): a subtle, slow animation — e.g. a
  180°/360° rotate or a flip every ~2s, ease-in-out, infinite. Keep it gentle, not
  spinning fast (it's a calm "working" cue, not a loading frenzy).
- Respect prefers-reduced-motion: wrap the animation in
  @media (prefers-reduced-motion: no-preference) so users who disable motion see a
  static clock.

Verify: start an analysis → the clock animates smoothly and CONTINUOUSLY, the
seconds counter still ticks up every 8s, and the animation does NOT reset/stutter on
each 8s update. No console errors. Backend untouched.
