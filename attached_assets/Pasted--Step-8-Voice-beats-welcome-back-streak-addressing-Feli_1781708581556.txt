# Step 8 — Voice beats (welcome-back + streak, addressing Felix)

**Goal:** the warmth layer. Two deterministic, rule-fired beats woven into Sara's single reply, addressing the learner as **Felix**:
- **Welcome-back** — first message of a NEW session that followed a gap, when a recap exists → opens by welcoming him back and referencing last time.
- **Streak** — when `streak_days` hits a milestone (3 or 7) → a brief celebration.

Both are **runtime prompt instructions** prepended into the one reply (not separate voice messages, not `sara_beats` table rows — the table has no `welcome_back`/`streak` scenario and the welcome-back is inherently dynamic). No migration.

## What changes & why
1. **Streak-keeping** (NEW plumbing — nothing maintains it today): in `_persist`, update `sara_state.streak_days` + `last_practice_date` based on the date gap. Prerequisite for the streak beat.
2. **Beat decision** in `_prepare`: it already knows if a new session was opened (it does the expiry) and reads `sara_state`. Compute a `beat_instruction` string and return it.
3. **Inject** the beat into the prompt for that one turn via `_think` → `_build_system_prompt`.
4. **Clear the recap** after a welcome-back fires, so it only triggers on the FIRST message of the new session, not every message.

## Change 1 — streak-keeping in `_persist`

`_persist` already upserts `sara_state` during calibration. Add streak maintenance. Replace the calibration upsert's column list so it ALSO sets streak fields — but streak logic depends on the PRIOR `last_practice_date`, so read it first. Insert this block inside `_persist`, right AFTER the `sara_turns` INSERT and the `sara_sessions` UPDATE, BEFORE the calibration block:

```python
        # --- streak maintenance ---
        cur.execute(
            "SELECT last_practice_date, streak_days FROM sara_state WHERE tg_user_id=%s",
            (tg_user_id,),
        )
        srow = cur.fetchone()
        today_q = "current_date"
        if srow and srow[0] is not None:
            last_date, streak = srow[0], (srow[1] or 0)
            cur.execute("SELECT (current_date - %s)", (last_date,))
            gap_days = cur.fetchone()[0]
            if gap_days == 0:
                new_streak = streak                  # already practised today
            elif gap_days == 1:
                new_streak = streak + 1              # consecutive day
            else:
                new_streak = 1                       # gap broke the streak
        else:
            new_streak = 1                           # first ever practice
        cur.execute(
            "INSERT INTO sara_state (tg_user_id, streak_days, last_practice_date, updated_at) "
            "VALUES (%s, %s, current_date, now()) "
            "ON CONFLICT (tg_user_id) DO UPDATE "
            "SET streak_days=EXCLUDED.streak_days, last_practice_date=current_date, updated_at=now()",
            (tg_user_id, new_streak),
        )
```

> This and the existing calibration upsert both touch `sara_state` — both use `ON CONFLICT DO UPDATE` on disjoint columns, so they compose safely in the same transaction.

And add the milestones reader near `_get_config_int`:

```python
def _streak_milestones(cur) -> set:
    cur.execute("SELECT value FROM sara_config WHERE key='streak_milestones'")
    r = cur.fetchone()
    if r and r[0]:
        out = set()
        for part in str(r[0]).split(","):
            part = part.strip()
            if part.isdigit():
                out.add(int(part))
        return out
    return {3, 7}
```

## Change 3 — `_think` accepts + injects the beat

```python
def _think(transcript: str, history: list, cefr_band, beat_instruction: str = ""):
    c = _get_anthropic()
    messages = list(history) + [{"role": "user", "content": transcript}]
    system = _build_system_prompt(cefr_band)
    if beat_instruction:
        system = system + "\n\n" + beat_instruction
    response = c.messages.create(
        model=SONNET,
        max_tokens=1024,
        system=system,
        messages=messages,
    )
    raw = response.content[0].text.strip()
    data = safe_parse_json(raw)
    reply = (data.get("reply") or "").strip()
    assessment = data.get("assessment") or {}
    if not reply:
        logger.error(f"Sara _think: no reply parsed from: {raw[:200]!r}")
        return "Hmm, one moment — could you say that again?", {}, False
    return reply, assessment, True
```

> The beat instruction is appended AFTER the level block but the OUTPUT CONTRACT still leads the prompt — JSON discipline unaffected. The beat goes inside the `reply` field like everything else.
